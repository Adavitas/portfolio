Case study / Systems

Minishell

Minishell is a collaborative C implementation of a focused Unix shell, connecting tokenization and syntax trees to processes, file descriptors, environment expansion, built-ins, heredocs, and signal behavior.

Type
Collaborative Unix shell
Stack
C, Unix, Readline
Focus
Parsing and processes

What it does

Readline input moves through lexical analysis, quote-aware expansion, parsing, and execution. Commands can form pipelines, redirect streams, update shell state through parent-run built-ins, or launch external programs with inherited environments while preserving exit statuses.

Key engineering

  • Token types retain quote context so variable expansion and the previous exit status occur at the correct stage.
  • An abstract syntax tree fixes command, pipeline, and redirection order before process creation.
  • Centralized descriptor cleanup, syntax checks, heredoc handling, and signal paths define predictable failure behavior.

Case study / Algorithms

Push Swap

Push Swap validates integer input, stores ranked values in linked-list stacks, and prints a legal instruction sequence that sorts stack A under a deliberately restricted operation set using C and Make.

Type
Constrained sorting program
Stack
C, linked lists, Make
Focus
Ranking and operation planning

What it does

The program can only swap, push, rotate, or reverse-rotate two stacks. Dedicated small-input strategies handle short permutations, while larger inputs move ranked chunks before rebuilding the sorted primary stack in order.

Key engineering

  • Validation rejects malformed numbers, duplicates, and values outside the signed integer range.
  • Relative ranks separate movement planning from each input value's original magnitude.
  • A companion checker applies instructions independently and reports whether the final state is sorted correctly.

Case study / Games

so_long

so_long is a 2D MiniLibX game in C where the player crosses a map, collects every item, and unlocks the exit while each movement is counted.

Type
2D grid game
Stack
C, MiniLibX, X11
Focus
Parsing and reachability

What it does

The program loads a rectangular .ber grid, validates its symbols and enclosing walls, then renders 32-pixel XPM tiles. Keyboard hooks move the player and redraw only the changed cells after every step.

Key engineering

  • Flood fill runs on a duplicate map to prove every collectible and exit is reachable.
  • Validation rejects malformed dimensions, unsupported tiles, missing entities, and maps larger than configured limits.
  • Window, sprite, map, and movement paths share cleanup and explicit, safe error handling.

Case study / Games and systems

cub3D

cub3D is a collaborative C graphics engine project that renders a textured first-person maze from a validated 2D map, with interactive doors, mouse look, and wand-driven lighting.

Type
Collaborative raycaster
Stack
C, MiniLibX, X11
Focus
Rendering and map parsing

What it does

For every screen column, the renderer performs DDA traversal, calculates perpendicular wall distance, and samples a wall slice. Separate passes add angle-based sky, floor casting, fog, the minimap, and HUD effects.

Key engineering

  • The parser validates texture paths, RGB values, player orientation, wall enclosure, and door placement.
  • Closed doors participate in both collision checks and ray hits until the player opens them.
  • Animated wand state dynamically controls local lighting, glow, sparkles, and first-person sprite frames.

Case study / Systems

Philosophers

Philosophers models the Dining Philosophers concurrency problem in C, running one POSIX thread per philosopher plus a monitor thread while mutexes coordinate shared forks, timestamps, output, meals, and simulation state.

Type
Concurrency simulation
Stack
C, POSIX threads, mutexes
Focus
Synchronization and timing

What it does

Each philosopher cycles through eating, sleeping, and thinking until the monitor detects starvation or every required meal is complete. Millisecond timestamps make thread activity observable while shared-state reads remain synchronized.

Key engineering

  • Odd and even philosophers acquire forks in opposite orders to break circular waiting.
  • Even threads start staggered, and odd table sizes receive calculated think time.
  • The monitor locks meal state before checking last-eat timestamps and completion counts for every philosopher.
